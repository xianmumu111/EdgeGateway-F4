| 7 | DEVLOG 补 9/18 那一条 | **「卡点」必须自己写** |

### 第 1 项：为什么必须改

```
[RPT][S0] TX: 01 03 00 00 00 02 C4 0B[RPT][S0] RX: 01 03 04 ...
                                      ↑ 粘一行了
```
RX 那行有 `\r\n`，TX 那行没有。补上就行。

### 第 2 项：不是 bug，是定时炸弹

```c
if(osMessageQueuePut(s_q_sample,&s,0U,0U) != osOK)
s_dropped++;
```

**语义是对的**（`if` 不带括号只管紧随的一条语句），但缩进写成同一级，
以后你想在 if 里加一行 `uprintf("drop\r\n")`，**它会在每次循环都执行**。
加括号：

```c
if (osMessageQueuePut(s_q_sample, &s, 0U, 0U) != osOK) {
    s_dropped++;
}
```

### 第 3 项：顺手的清理

`defaultTask` 是 CubeMX 默认生成的空任务（`for(;;) osDelay(1);`），
优先级 `osPriorityNormal` **比 `taskModbus`（BelowNormal）还高**。
现在无害（它有 `osDelay`），但留着是个说不清的东西。删掉。

> 可选：`.ioc` 里 FreeRTOS 的 `configMAX_PRIORITIES` 默认是 **56**，
> 你一共 3 个任务。FreeRTOS 找最高优先级就绪任务要扫这个数，
> 56 会让它每次调度多花时间。改成 **8** 能覆盖到 `osPriorityRealtime`，
> 调度更快。这是面试能讲的一条优化，但**今天不做也行**，别在主线里掺。

## 2. 今天主线：把波特率从 9600 提到 115200，看整套链路还成不成立

### 为什么是这个

- **不需要任何新硬件**（RS485 模块、SD 卡、ESP 都还没到）
- 你现在的分帧判据全是在 9600 下验证的。**没被别的条件验过的东西，不能说它成立**
- 高波特率会同时打到三个地方：从站 t3.5 判据、主站 IDLE 分帧、`HAL_GetTick()` 的精度

### ★ 我预计你会撞到的坑（先看，别蒙着头改）

**从站的 t3.5 判据在高波特率下会失效。**

`nodes/f103_slave/Core/Src/modbus_slave.c:36-40`：

```c
#if MODBUS_BAUD > 19200
#define MODBUS_T35_MS  2          /* 固定 2ms */
#else
#define MODBUS_T35_MS  ((35000UL / MODBUS_BAUD) + 1)   /* 9600 下 = 4ms */
#endif
```

而判据在 `modbus_slave.c:125`：

```c
if ((uint32_t)(HAL_GetTick() - last_rx_tick) < MODBUS_T35_MS)
```

**`HAL_GetTick()` 是毫秒分辨率。** 115200 下：

| 量 | 值 |
|---|---|
| 1 个字符 | **86.8 µs** |
| 3.5 字符（理论） | **304 µs** |
| 规范规定（>19200 固定） | **1750 µs** |
| 你现在的宏 | 2 ms |
| `HAL_GetTick()` 分辨率 | **1000 µs** |

⇒ 用 1ms 精度的尺子去量 1.75ms 的间隔，**误差能到 57%**。
表现出来就是：偶尔把一帧切成两半，或者两帧之间等太久。

### ⚠️ 顺带纠正我 9/17 说错的一句话

我 9/17 记的是「2ms 偏激进，现场长帧可能误判帧结束」。**这句说反了。**
2ms > 1750µs，等得**更久**，是**保守**方向，不会误判帧结束；
代价只是每帧多等 0.25ms，且**不符合规范**。
真正危险的是 t3.5 设得**太小**。认错。

现在跑的是 9600，走 else 分支（4ms），**高波特率那个分支根本没被执行过** ——
这也是今天要做这个实验的理由之一：**没跑过的代码路径，不算数。**

### 步骤

**第一步：先改 38400（保守一点，别一步跳 115200）**

1. 两边 `.ioc` / 初始化里把波特率都改成 **38400**（主从必须一致）
2. 从站：`MODBUS_BAUD` 宏改 38400
3. 编译烧录两边
4. 跑五步轮询，把输出贴出来

**第二步：预期的问题和修法**

如果从站开始偶发丢帧/拆帧，正解是**把 t3.5 判据改成微秒级**：

- 用 TIM（比如 TIM2）做自由运行的 µs 计数器，替代 `HAL_GetTick()`
- 或者把 SysTick 提到 1kHz 以上（不推荐，会拖慢内核）
- 判据改成 `now_us - last_rx_us < 1750`

**第三步：成了之后再上 115200**，重复验证

9600 下的耗时是基准，波特率翻 4 倍（38400）时：

| 步骤 | 9600 实测 | 38400 理论（= 9600 ÷ 4） | 你的实测 |

| S0 读 | 23ms | ≈ 6ms | ? |
| S3 异常帧 | 19ms | ≈ 5ms | ? |
| S4 掉线 | 208ms | ≈ 208ms（超时是软件定的，不变） | ? |

**S4 不应该变快** —— 200ms 是软件超时，跟波特率无关。
